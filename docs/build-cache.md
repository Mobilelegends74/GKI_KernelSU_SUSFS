# Кэш сборок GKI

Kleaf уже использует `--config=fast`, включающий local mode. Для повторных
сборок сохраняются оба разных кэша:

- `/home/runner/.cache/bazel`: результаты отдельных действий Bazel;
- `/home/runner/.cache/kleaf`: Kbuild OUT_DIR, включая объектные файлы ядра.

Каждый успешный запуск сохраняет новый snapshot с уникальными run ID/attempt.
Следующий запуск восстанавливает последний совместимый snapshot по префиксу.
Фиксированный точный ключ не используется: GitHub не перезаписывает существующие
кэши. Семейства разделены по ОС runner, версии ядра, feature set, варианту,
ревизиям базы ядра, Kleaf и prebuilts. Для старых build.sh-сборок остаётся ccache.

После всех патчей и до компиляции `gki-cache-state.py` сравнивает SHA-256 и
права исходников с сохранённым манифестом. Только полностью совпадающим файлам
возвращается прежний mtime. Новым и изменённым файлам обеспечивается свежий mtime,
включая исходники из архивов с сохранёнными старыми датами:
Kbuild должен пересобрать их и зависимые объекты. Исходники и настройки не
подменяются данными из кэша. После Normal и Bypass сохраняется новый манифест.

В Actions Summary выводятся ключ восстановления, новый ключ, объём обоих
каталогов и число `.o`. В журнале `Save updated Kleaf compilation snapshot` должен быть подтверждён
успешный upload. Первый запуск новой схемы будет холодным. Скорость повторного
запуска зависит от изменений исходников/конфига, runner и стоимости LTO.

Сохраняется полный каталог incremental build, без удаления объектов ради
искусственного лимита. Доступное хранилище и вытеснение старых snapshots
ограничиваются квотой GitHub Actions репозитория. Частично неуспешные сборки
новый snapshot не публикуют. Эта настройка не меняет функции или защиты ядра.
